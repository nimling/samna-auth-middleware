# Claimius functions

The function surface of the `claimius` schema `samna_auth_middleware` ships: `prophet/database` for samna_auth, `disciple/database` for every disciple. Function names here follow the SQL; where `~/.claude/rules/claimius.md` disagrees, this file wins. Long form design: `samna_auth_middleware/.nimpress/claimius/`.

## Materialization is paid on read

A write settles only the acting user on the rows it names and raises the area in `access_diff`, stamped with its transaction and the object's owner root. Each other user settles their share on their next `get_*` read: a listing settles the reader's share of every area raised since its cursor, `user_activity.settled_txid`, in one pass, and a check settles the one pair when an area on its nodes is newer than the pair's mark, `user_object.settled_txid`. `drain_access_diff` settles frequent readers off the request path and folds usage and `user_users_diff`, each step in its own subtransaction, and returns `(settled, failures)`; `trim_access_diff(keep)` removes the areas every cursor active within the `access_diff` retention has passed, or every finished area when none is, recording the position in `access_trimmed_txid`, on the prophet per app with a `prophet_state` row created for an app that has none. `trim_sync_event(stale_after)` trims the feed by the disciples' cursors on the prophet. Retention: `prune(p_settings JSONB) RETURNS BIGINT` on both sets, `V2.4`. Every runtime table belongs to a kind: on the prophet `audit` (730 days), `analytics_event`, `analytics_session`, `analytics_capture` and `analytics_heat` (`analytics`, 365), `notification` by `closed_at` and `sa_deleted_at` (365), `session`, `dpop_jti`, `jwks_cache`, `par_request`, `rate_limit` and `code` by `ends_at` and `revoked_at` (`token`, 7), `consent` by `revoked_at` and `peer_collision` (`log`, 180); on the disciple `audit`, `notification` and `dpop_jti`. `p_settings` sets days per table (`<table>_days`) or per kind (`<kind>_days`) and a size per kind (`<kind>_size_mb`) or for all (`size_mb`, 4096). A table under its size is left alone; over it, every row whose time column is older than its days is deleted; 0 days leaves a table alone. When `public.prune(JSONB)` exists it runs after with the same settings and its count is added. Go: `shared.Retention` is `map[string]int`, `RetentionEnv()` reads `SAUTH_RETENTION`, `(*DB).Prune(ctx, r)` calls the function and `(*DB).PruneLoop(ctx)` runs it hourly with the app's `DB.Retention(ctx)` laid over the env, started by each role's `sam.Init` under `shared.LeadSync` with `shared.RetentionLockKey`. No retention table, kind table, class, endpoint or cold storage; application data is never aged. Never assume another user's `user_object` row exists after a write. `reconcile_if_pending` runs only at the top of the `get_*` family, so a direct SELECT never settles. `notify_object` settles the pair of every user who may hold the object before it fans out, so a reader who has not read since the last write is reached.

## Reads

1. `get_access(user, app, object_id, object_type, min)`: strongest grant, at most one row, carries `user_claim_id`, the actor token for `sa_created_by` on follow on writes. When only the creator's `direct_grant` covers `min`, the row is `direct_grant` true, `claim_name` `direct` and no `user_claim_id`, the same verdict `get_objects` lists, so a row with no owner stays reachable by id to its creator.
2. `get_direct_access(user, app, object_id, object_type, required?, raise?, settle?)`: closest ancestor grant over owner, location and parenthood chains; same row shape.
3. `get_objects(user, app, type, min, after?, limit?)`; `get_organizations`, `get_locations`, `get_secrets` are one `get_objects` page. `get_users`, `get_claims`, `get_audit`.
4. `get_user_access(actor, app, target, min)`: target as external_id, user_id or row id, resolved in that order.
5. `get_scope_access(user, app, jsonpath, min)`: object less scope bindings.
6. `get_owner_graph` and `get_claim_graph(user, app, start_id?, depth?, min?, width?, sort?, next_id?)`: flat rows `object_id, object_type, label, parent_id, data{access, level}`. `width` bounds rows returned, not rows read. The default claim graph is cached in `claim_graph_cache`.
7. `search(user, app, query, types, min, limit, offset)`: ranked by text match plus the reader's decayed usage.
8. Listings and graphs return no `user_claim_id`; call `get_access` on the object before acting.
9. `shared.UserWhere(user, req)` filters `samna_user` listings: a user always reads its own row, and `type = 'system'` users stay hidden from every other user.
10. Lookups by id on a disciple, with no reader and no access filter, soft deleted rows included, for a row a read already admitted: `get_users(user_ids, ids, emails?, external_ids?)`, `get_organizations(ids, owner_ids, external_ids?)`, `get_locations(ids, parent_ids, external_ids?)`, `get_claims(ids, owner_ids)`, `get_grants(ids?, user_ids?, claim_ids?, owner_ids?, clients?)` over `user_claim`, `get_bindings(object_type?, object_ids?, claim_ids?)` over `claim_object` with `effective_access` on each row, `get_user_identities(user_ids)`, `get_object_types()`. Every given list applies; no list gives no rows; an email compares without case. Pass both leading arrays, cast `?::uuid[]`, NULL for an unused one. Go: `GetUsersMany(ctx, userIDs, ids, emails, externalIDs)`, `GetOrganizationsMany(ctx, ids, ownerIDs, externalIDs)`, `GetLocationsMany(ctx, ids, parentIDs, externalIDs)`, `GetClaimsMany`, `GetGrants(GrantFilters)`, `GetBindings(BindingFilters)`, `GetUserIdentities`, `GetObjectTypes`.
11. `get_object_usage(user, object_ids, object_types?)`: per object its `object_info` name and the reader's `used_count`, NULL without a pair; a NULL type takes the type of the reader's pair. Go: `GetObjectUsage`.
12. `get_relations(user, ids?)` on a disciple: the reader's live `user_relation` rows. Go: `GetUserRelationsQuery`, `GetRelation`, `GetRelationQuery`. `get_audit(user, required, limit, offset, ids?)` on a disciple: with `ids` only those rows; the feed carries the prophet's audit rows of the app to the disciple, so the trail there holds the claimius writes beside the host's own. Go: `GetAudit(ctx, user, required, ids)`. `get_descendants(object_id)`: the typed walk for whichever registered type holds the id. Go: `GetDescendants`.
13. The views `get_users`, `get_organizations`, `get_locations`, `get_claims`, `get_grants` are every row of `samna_user`, `organization`, `location`, `claim`, `user_claim`, soft deleted included, created in `V6.0` with `SELECT` for `claimius_reader`. They are the read surface of bun selects and belongs-to joins: the `shared` models carry `select:claimius.get_<name>` beside `table:`, so bun reads the view and writes the table. A consumer model over a claimius table adds the same `select:`. Never name a `claimius` table in app SQL; a join names the view.
14. `search([app,] user, query, object_types?, required?, object_ids?, exclude_object_ids?, owner_subtree_ids?, parent_id?, parent_type?, limit?, offset?)`: the scoped overload beside the short one, on both sets, with a `total_count` column on every row for offset pagination. An empty query lists every accessible object in scope ranked by decayed usage. The read starts from the smallest of three sets: the scope's closure rows when `_search_scope_smaller` counts them no more than the reader's pairs, the query's postings when `_search_text_smaller` estimates them fewer, otherwise the reader's range. A non empty query also adds the rows of every registered search source of the requested types, each kept only where the reader holds a pair. `upsert_search_source(object_type, fn regprocedure)` registers a host function `fn(object_type text, query text, scope_ids uuid[]) RETURNS TABLE(object_id uuid, score real)` for a registered type, one function may serve several types, score clamped to `[0, 1]`; `delete_search_source(object_type)` removes it; both are revoked from `claimius_reader`. Use the scoped overload with one scope id for "search inside this organization"; never list the reach with `get_objects` and filter it. `V2.4__claimius_functions_external.sql`, the table `search_source` and the type `search_hit` in `V1.1`.
15. Both sets, `get_ancestors(p_object_type, p_object_id)` and `get_descendants(p_object_type, p_object_id)`: the combined walk across the owner, location and parenthood trees, rows `object_type, object_id, hop, tree_type`. `get_ancestors` is in `V2.2__claimius_functions_internal.sql`, `get_descendants` in `V2.4`.
16. Both sets, `get_graph_links_owner` and `get_graph_links_claim([app,] user, required?, include_types?, exclude_types?, start_id?, depth?, width?, sort?, next_id?)`: the link builders behind the two graphs, returning one jsonb with `links`; `sort` is `name` or `usage` and `width` at least 0, else SQLSTATE `22023`. Owner defaults `required` to 4, claim to 0. `V2.4`.
17. Both sets, `get_secret_value(user, secret_id) RETURNS TABLE (value, app_id)`: the stored ciphertext of one secret, with the id of the app that wrote it, when the user is active in that app and `get_access` gives it read on the secret, through the claim `insert_secret` bound for its creator or any claim held on it; no row for anyone else, an unknown and a deleted secret. Go: `SamnaSecret.Resolve`. `V2.4`.
18. `get_code([app,] hash)`: the code whose value hashes to `hash` as JSON with `guest_mode`, `guest_user_id` and `guest_user_claim_id`, or NULL; the caller checks window, count and `revoked_at`. `get_codes([app,] claim)`: a claim's codes, revoked ones included. Disciple set, `get_guest_access(object_type, object_id)`: the guest of an open guest claim covering the object, capped at READ, with its `user_id`; `MutationAccess`, `GetAccess`, `MutationAccessMany` and `ObjectWhere` call it for `shared.AnonymousUserID`. `get_access` answers a user of type `guest` nothing past READ and returns its mask with the READ bit only. `V2.4`.
19. Prophet set, `get_sync_consumers(app_id)`: one row per consumer of the app's feed, lowest cursor first: `consumer_id`, `peer`, the cursor `txid`, `seq`, `last_contact_at` and `in_contact` (within 7 days, the trim's rule), the app's `head_txid`, `head_seq` from `get_sync_seq` and `trimmed_txid`, `trimmed_seq` from `prophet_state`, `behind` counted up to 1,001 as `check_sync_cursor` counts, and the first event after the cursor as `next_txid`, `next_seq`, `next_operation`, `next_event_type`, `next_payload_id`, NULL at the head. Both apply the feed's filters for that consumer, `app_handover` only for a peer; `update_sync_cursor(app, consumer, txid, seq, peer)` records `peer` from the pull. One descent of `idx_sync_event_app_txid_seq` per consumer. Go: `prophet/sdb.GetSyncConsumers(ctx, appID)` returns `[]shared.SyncConsumer`; the middleware mounts no route. `V2.4`.

## Writes

Write functions return one jsonb keyed by table: `(v -> 'claim' ->> 'id')::uuid`.

1. `claim`, `user_claim`, `claim_object`: `insert_*`, `update_*`, `delete_*` only; `update_claim` patches name, description, mask, inherits, level and type. `p_starts_at` and `p_ends_at` on `insert_user_claim` expire a grant at read time.
2. `samna_user`: `upsert_app_user`. Guests: `upsert_guest_user`; `update_claim_guest([app,] claim, actor, [guest,] mode)` makes a claim a guest claim, `open`, `code` or `off`, ensuring its guest. Codes: `insert_code([app,] actor, claim, hash, kind, ...)`, `delete_code([app,] actor, code)` revokes, `update_code_used([app,] hash)` takes one use in one statement, `redeem_code([app,] hash, user)` locks the code, takes a use and grants an invite's claim; Go `PostCode`, `DeleteCode`, `PutCodeUsed`, `PostCodeRedeem`, `PutClaimGuest` on a disciple route to `/sam/code` and `/sam/claim/:id/guest`, and `prophet/sdb` has the same with the app id first. Secrets: `insert_secret`; `SamnaSecret.Resolve(ctx, db, userID)` reads the value through `get_secret_value` and opens it with the seed `GetApp` returns: on a debug disciple `SAUTH_DEBUG_PRIVATE_SEED`, on the prophet the system app's opened from its wrapping under `SAUTH_MASTER_KEY`, and on a deployed disciple its own app's, fetched from `GET /sam/app` and held in memory by `shared.GetAppSeed`. Audit: `insert_audit`. External users: `PostUserFromToken` and `PostUserFromExternal`, routed to the prophet, which writes the `user_identity` row under the organization; the feed carries it to every app the organization is linked to, without `data`, and a forwarded identity resolves in any of those apps. Cross app: `merge_user`, prophet set only; samna_auth owns the merge flow and calls it from `samna_auth/internal/service/user.go` `MergeUser`. Profile, prophet set: `samna_user.profile` is one free form JSONB; `upsert_profile_item(p_app_id, p_user_id, p_field, p_item JSONB)` writes `{"<app_slug>": {"<field>": <item>}}` on every row of the user, `delete_profile_item(p_app_id, p_user_id, p_field)` removes the field or, with a NULL field, the app's whole object; both return the profile, P0404 when the user has no live row in the app, 22023 for a malformed field or a non object item. A disciple reaches them through `PUT /sam/profile`; the user's own keys are written on Samna Auth, and the sync carries the object. No `profile_item` table, no `GET /sam/profile`.
3. Apps: `upsert_system_app` bootstraps a prophet; `upsert_app(p_actor_user_claim_id, ..., p_parent_id)` creates every other app with its links, owner and default claims and grant; with `p_parent_id` it creates only an Initiate app row under that parent, in the parenthood tree of `samna_app`. Never INSERT `samna_app`.
4. Disciple bootstrap: `upsert_disciple_state(p_disciple_app_slug)`. Hybrid: `upsert_prophet_peer`, a prophet mirroring one app of a peer, with no `disciple_state` row.
5. Registration: `upsert_table_info` registers the named tables, idempotent; `delete_table_info` deregisters the named tables. Rerun `upsert_table_info` after adding `sa_parent_id`, `sa_root_id` or `sa_location_id`, after the migration and backfill.
6. `app_object`: `upsert_app_object`, `delete_app_object`, never direct. Roots: `upsert_root_organization`, idempotent on app and name.
7. Direct INSERT or UPDATE: `organization`, `location`, `samna_client`, `object_field`, `user_field`, `user_relation`, `object_asset`, `prophet_state`, `disciple_state`, `samna_app` and `samna_secret` updates.
8. Never write: `user_object`, `object_info`, `user_users`, `user_users_diff`, `inheritance_info`, `table_info`, `sync_event`, `access_diff`, `user_activity`, `claim_graph_cache`, `peer_collision`, `used_count`, `last_used_at`. There is no `object_users`, `access_diff_user` or `reconcile_queue` table.
9. Bind every created resource with `insert_claim_object` before any read looks for it. Exempt: `samna_user` and claims themselves.
10. Order inside an app: org, location, app row, then `insert_claim`, `insert_claim_object`, `insert_user_claim`.
11. `_check_claim_composition` refuses a binding that hands out more than the actor holds. Two first bindings are judged on owner of an organization instead: an app's first binding (`upsert_app`) and a user's first binding under an org (`insert_organization_user`).
12. A binding on a row the prophet holds no `object_info` row for, outside `claimius.*`, is judged on the actor's hold on the binding's owning organization, and by the creator rule the disciple applies: a routed binding carries the row's `sa_created_by` as `object_created_by`, `PostClaimObject` sets it as `claimius.object_created_by` for its transaction, and when that is a live `user_claim` of the actor in the binding's app and the owning organization is live, the actor holds owner, write, read and execute on the row.
13. Both sets, notifications: `notify_object(app, title, description, style, type, link, object_type, object_id, created_by, owner_id, repeats_at)` writes one `notification` per user holding read on the object, the actor `created_by` excluded, after settling every pair that may hold it; `notify_user` takes the same eleven arguments plus `user_ids` and writes one per named active user in the app. Both return the rows inserted. `V2.4`.
14. Both sets, `app_cost`: a routed table like `claim_object`, the cost ledger of an app, one live row per app, module and ref, written by the app's own actor through the builder in one of three forms, row, items or event, which routes it to `/sam/cost`, where the prophet stamps the app and its organization, normalises the input, checks `detail` against the row's `schema` when one is set and replaces the ref; `kind` is usage, fee, period or credit, `period_start` and `period_end` the window, `supersedes_id` a correction's target left out of every sum, `schema` a JSON Schema document whose `x-samna.accumulate` names method, proration and group. Read back in buckets with `get_app_cost([app,] user, module?, from?, to?, granularity?, status?, subject_type?, subject_id?)`, granularity hour, day or month, fee and credit in the bucket of their start, usage and period prorated by overlap, grouped by module, kind, schema `$id`, group key, unit and currency with the hours and the row count; the prophet checking the reader through `get_access` on the app row, the disciple, with no app argument, on the owning organization. Go: `shared.GetAppCost` with `AppCostQuery` on both roles, `disciple/sdb.PutAppCost` with `AppCostInput` on the disciple, `shared.CostSchema` the default schema document. `V1.1` and `V2.4`.

## Access mask

1. Owner 1, write 2, read 4, execute 8, deny 16, member 32; `ACCESS_ALL` is 15. Go constants: `shared.ClaimAccess` in `samna_auth_middleware/shared/models.go`.
2. On a grant, owner implies write, read, execute; write implies read and execute; execute implies read. Member stands alone.
3. A binding narrows its claim: `claim & expand(coalesce(binding, claim))`. NULL binding means the claim mask.
4. `claim.level` decides between a grant and a deny, not access, and only `claim.level` compares: a deny at level N subtracts from every grant at a level below N whatever its class, a grant at a level above the deny keeps its bits, and at equal levels the classes of point 5 decide bit by bit; level 0 everywhere is the class rule alone. The `level` of an organization or location is tree depth.
5. Deny: a claim with bit 16 and the bits to subtract. Bound on the object it subtracts from every grant; through a tree only from tree grants. The remainder is closed under implication. Reads never filter denies.
6. Cascade needs `inherits` on both the claim and the binding.

## Scoping

1. `app_id` column: `samna_user`, `claim`, `user_claim`, `claim_object`, `user_object`, `user_users`, `user_relation`, `user_field`, `object_field`, `samna_client`, `samna_secret`, `audit`, `access_diff`. Always filter on it.
2. `organization` and `location` have no `app_id`; scope through `app_object_ids`, `app_has_object`, `apps_for_object` on the prophet.
3. The prophet refuses with P0403 a `claim`, `user_claim` or `claim_object` whose owning organization, or whose bound organization or location, is not linked to the row's app: `_check_app_scope` over `app_has_scope`. Link the organization first; an update that keeps app, owner and object passes.
4. A `user_claim` and a `claim_object` live in the app of their claim: the prophet refuses any other `app_id` with 23503 on `user_claim_app_claim_fkey` and `claim_object_app_claim_fkey`, over `claim_app_id_id_key`. Grant or bind a claim of another app with that app's id, never the calling app's.
5. Disciples carry no `app_object`: a disciple mirrors one app, the sync layer strips `app_id`, and the disciple's read functions take no app argument. Write the app filter on the prophet side only.
6. A registered table may omit `app_id`; it is inferred from `get_app_id()`. On a multi app prophet the column is required.
7. `get_app()` returns the system app and raises on a pure disciple; `get_disciple_app()` raises on a prophet and a hybrid. On a hybrid use `get_app_id()`. These helpers ship in the prophet set only, in `V1.1`.

## Asset links

`object_asset` links an asset its home app stores to a `claimius.*` object; the asset row and its bytes stay in the home, only links sync. Long form: `samna_auth_middleware/.nimpress/claimius/assets.md`.

1. Not a registered access table: access to a link is READ on its object, for a `samna_user` self or what `get_user_access` resolves. Read with `get_object_assets`, in Go `GetObjectAssets` and `GetObjectAsset`.
2. A link reaches the apps `apps_for_object` names: an organization's or location's `app_object` apps, every app holding the user, the app itself, a claim's app, else the home. A late `app_object` link or `samna_user` row publishes the object's live links; never write `sync_event` for them.
3. Prophet: direct insert, update or soft delete with `app_id` the home. Disciple: the builder routes `shared.ObjectAsset` to `/sam/object_asset`, where the prophet checks WRITE on the object for the forwarded actor, a `samna_user` through `get_user_access`, any other object through `get_access`, and stamps owner and grant; on the actor's own user the grant is its default claim grant in the home app, refused without one.
4. A file is fetched through the prophet only: the consumer route calls `disciple/echo.GetObjectAssetData`, the prophet serves or relays to the home's `/asset/:id/data`, and the home answers from the host's `sdb.Options.AssetSource`. Every hop passes `Content-Type`, `Content-Length`, `ETag`, `Last-Modified` and `Cache-Control` through; the middleware caches nothing, a host `AssetCache` is used only while fresh.

## Types and trees

1. Object types are schema qualified everywhere; `upsert_table_info` raises on a bare name. `shared.ResolveObjectType` resolves bare claimius names and passes consumer types through; `ObjectTypeOf` returns the model `table:` tag as written; `ObjectType.Validate` is the consumer's opt in check.
2. Composite id: `claimius.composite_id(type, id)` gives `<schema>.<table>:<uuid>`.
3. Roots self reference. Children set the parent and leave `sa_root_id` NULL for the trigger.
4. Cross root moves: `migrate_root(object_type, object_id, new_root_id)` only, flagged for human review.

## Traps

1. Role grants live in `V6.0__claimius_grants.sql`; never call `_grant_prophet_roles` or `_grant_disciple_roles`. The eight baseline files per role are the whole schema; a `V5.*` or `V1.2` file is dead and never cited.
2. A write to an app another prophet is home for raises `P0409` with the home in the hint; `/sam` answers 409 with `SAuth-Home`. Send the write there.
3. `replay_mode` is set only by the middleware: the sync pull, and the local copy of a routed write's answer, which goes through the same `shared.ApplyEvent` as its feed row and sets only the columns the answer carries. Never by app code.
4. Sync lag: compare `disciple_state (last_applied_txid, last_applied_seq)` on the disciple with `get_sync_consumers(app_id)` on the prophet, Reads 19; never SELECT `sync_consumer` or `sync_event`.
5. Stale pair: `recompute_user_object(app, user, type, id)`, rarely needed.
6. Public surface prefixes: `get_`, `insert_`, `update_`, `delete_`, `upsert_`. `_` prefixed functions are internal.
7. An organization or location unlinked from the app arrives on the feed as a delete and is retired on the disciple, `sa_deleted_at` set, never removed: the host's rows and the claimius rows under it keep their references, and the access derivation gives nothing under a retired organization.
8. A routed write the host's own transaction then failed after leaves its binding or virtual claim on the prophet; the disciple's leader removes those every 10 minutes through `CleanOrphans`, over `get_orphan_bindings` and `get_orphan_claims`, after a 10 minute grace. Never on the request path.
