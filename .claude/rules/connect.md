# How a consumer connects

1. A disciple binds to one prophet through `SAUTH_ENDPOINT` in its own environment, and is the only part of a service that reaches it: `../.claude/rules/platform.md` Prophet and disciples.
2. `SAUTH_APP_SLUG` and `SAUTH_APP_SECRET` name the app; the app and its secret come from the workspace `apps` skill, never a seed. `SAUTH_REDIRECT_URI` and `SAUTH_PAGE_REDIRECT` are the login return.
3. `PG*` is the consumer's own database holding its replicated `claimius`; `SAUTH_REPLICA_DSN` an optional read replica.
4. Sync is pull only: `sam.SyncStart` reads `/sam/sync/:cursor` from the prophet. One puller per database. `SyncStart` also fetches the app's own `private_seed` from `/sam/app` and holds it in memory only, for `SamnaSecret.Resolve`; the prophet stores it wrapped under `SAUTH_MASTER_KEY`.
5. `SAUTH_DEBUG_USER_ID` and `SAUTH_DEBUG_CLIENTS` turn on debug mode, which skips the sync and acts as the debug user. Set only in a local `.env`.
6. `SAUTH_CLIENT_ID` and `SAUTH_CLIENT_SECRET` are the consumer's machine client for service to service calls. A cli's machine client sends its pair as Basic auth to the service, which `smw.UserAuthMiddleware` checks against the replicated `samna_client`.
7. Cli login: a cli opens the service's own `/api/auth/login` with its `cli_challenge`, and `cli_redirect` with `cli_state` for a loopback or neither to paste; `GetCallback` hands the code to the cli without exchanging it. `sam.RegisterCli(e.Group("/api/auth"))` mounts `POST /api/auth/cli/token` (the `authorization_code` grant with the cli's `code_verifier`, and `refresh_token`) and `POST /api/auth/cli/revoke`, rate limited, forwarding to the prophet's `/oauth/token` and `/oauth/revoke` with `SAUTH_APP_SLUG` and `SAUTH_APP_SECRET`. The disciple stores nothing of a cli login, and a host carries no cli login handler or table of its own.
8. Telemetry: the host calls `nimtel.Init` and mounts `smw.TelemetryMiddleware()` before the auth middleware; the Container Apps env supplies `OTEL_EXPORTER_OTLP_*`.
9. Consumers on v2: samna_auth (prophet), bookable_server, nimployer, samna-sync, samna_connect, samna_sign, hvergel, samna-developer. `bookable_server` and `samna.io` stay on v1. `../.claude/scripts/repos.sh` prints every pin.
