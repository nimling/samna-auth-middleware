# How a consumer connects

1. A disciple binds to one prophet through `SAUTH_ENDPOINT` in its own environment, and is the only part of a service that reaches it: `../.claude/rules/platform.md` Prophet and disciples.
2. `SAUTH_APP_SLUG` and `SAUTH_APP_SECRET` name the app; the app and its secret come from the workspace `apps` skill, never a seed. `SAUTH_REDIRECT_URI` and `SAUTH_PAGE_REDIRECT` are the root app's login return. An Initiate app of the root, another frontend on its own origin, logs in through `/api/auth/<slug>/login` with `redirect_uri=<SAUTH_REDIRECT_URI>?app=<slug>` registered on it, and returns to its first redirect URI; logout is `/api/auth/<slug>/logout`. Its registered callback, `cookie_domain`, `cookie_same_site` and origins come from samna_auth; a host mounts `smw.InitiateMiddleware` and uses `smw.GetOriginAllowed` for CORS. How the disciple loads them: `.nimpress/claimius/apps.md` Initiate apps.
3. `PG*` is the consumer's own database holding its replicated `claimius`; `SAUTH_REPLICA_DSN` an optional read replica.
4. Sync is pull only: `sam.Init` reads `/sam/sync/:cursor` from the prophet. One puller per database. The app seed `SamnaSecret.Resolve` uses: `.nimpress/disciple.md` What the disciple never does.
5. `SAUTH_DEBUG_USER_ID` and `SAUTH_DEBUG_CLIENTS` turn on debug mode, `.nimpress/index.md` Debug mode; `SAUTH_DEBUG_INITIATE_APPS=<slug>=<origin>,...` stands in for the Initiate apps there. Set only in a local `.env`.
6. `SAUTH_CLIENT_ID` and `SAUTH_CLIENT_SECRET` are the consumer's machine client for service to service calls. A cli's machine client sends its pair as Basic auth to the service, which `smw.UserAuthMiddleware` checks against the replicated `samna_client`.
7. Cli login: a cli opens the service's own `/api/auth/login` with its `cli_challenge`, and `cli_redirect` with `cli_state` for a loopback or neither to paste; `GetCallback` hands the code to the cli without exchanging it. `sam.RegisterCli(e.Group("/api/auth"))` mounts `POST /api/auth/cli/token` (the `authorization_code` grant with the cli's `code_verifier`, and `refresh_token`) and `POST /api/auth/cli/revoke`; how they reach the prophet and their limits: `.nimpress/compliance.md` C25 and C26. The disciple stores nothing of a cli login, and a host carries no cli login handler or table of its own.
8. Telemetry: the host calls `nimtel.Init` and mounts `smw.TelemetryMiddleware()` before the auth middleware; the Container Apps env supplies `OTEL_EXPORTER_OTLP_*`.
9. Which consumer pins which middleware version and schema `ref` is read live from `../.claude/scripts/repos.sh`, never from a file.
10. Access codes and the anonymous user: `smw.UserAuthMiddleware` resolves every route the same way, bearer, cookie, machine client, else the anonymous user `shared.AnonymousUserID` under `SAUTH_RATE_LIMIT` per `SAUTH_RATE_PERIOD` (60 per minute unless set, per replica), reading `samk`, `SAuth-Code` or the `__Host-sauth_samk` cookie and carrying a code the anonymous user's grant names in `options.samk` into the walk as `claimius.samk`. A public grant is written like any grant, `POST /sam/claim/:claim_id/user` with the anonymous user and `options`, changed with `PATCH /sam/claim/:claim_id/user/:id`; invite codes through `/sam/code`; a temporary user's token through `POST /sam/user/temporary`. The design is `.nimpress/claimius/users.md`, Three holders, Access codes and The guard.
11. Runners: a host makes the signal context with `signal.NotifyContext` and a run context it cancels after `e.Shutdown`, and starts its role once with `sam.Init(runCtx) error`, fatal on error. A host never calls `notification.Init` or `analytics.Init` and never passes a database. `uptime.Init(runCtx, logger, opts)` is the other host call. The host registers `notification.EndStreams` (and on a prophet `prophet/echo.EndStreams`) with `e.Server.RegisterOnShutdown`, shuts the http server down on the signal, cancels the run context, waits on `sam.Done()` and `uptime.Done()` and closes `sdb.Instance()` last. Each role owns its instance; `shared` holds none. There is no `Stop`. `.nimpress/disciple.md` Lifecycle.
12. Retention: `claimius.prune(p_settings JSONB)` on both roles, run once an hour by one replica through `shared/retention.go` `PruneLoop` under `shared.LeadSync`. `SAUTH_RETENTION` in `.env` is one JSON object of defaults, days per table (`<table>_days`) or per kind (`<kind>_days`) and a size per kind (`<kind>_size_mb`) or for all (`size_mb`), with lenient defaults (audit 730, analytics 365, notification 365, token 7, log 180, 4096 MB); the app's settings override it through `sdb.Instance().Retention`. A host with runtime tables of its own defines `public.prune(JSONB)` of the same shape, which `claimius.prune` runs after. No table, no registry, no endpoint, no class, no cold storage; application data is never aged, and `sync_event` and `access_diff` are trimmed by cursor, not by age. `.nimpress/disciple.md` Retention.
